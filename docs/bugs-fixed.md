# Bug Log And Fixes

This log captures the main defects found during the Postgres migration and browser-driven workflow pass, along with the fix that was applied.

| Area | Symptom | Fix applied | Validation |
| --- | --- | --- | --- |
| Database config | Development commands were still effectively split between SQLite and Postgres behavior. | `config/settings.py` now auto-loads `.env` and always uses PostgreSQL for `DATABASES["default"]`. | `manage.py migrate`, `manage.py check`, and `runserver` all worked against local Postgres. |
| Orders migration | `orders.0003_alter_order_payment_transaction` failed on PostgreSQL with a UUID-to-bigint cast error. | The migration was rewritten to add/backfill/remove/rename instead of using an unsafe direct cast. | Full migration run completed successfully. |
| IAM user creation | Signup and custom user creation failed because the wrong `Group` model was referenced. | The IAM user model now imports the local custom `Group`. | Signup and seeded-user flows worked again. |
| Checkout template | Checkout crashed with a Django template syntax error in payment selection logic. | The radio selection logic was rewritten into template-safe `{% with %}` usage. | Checkout page rendered successfully in the browser. |
| Customer navigation | Customers could hit dead-end account/orders pages and a reporting link that returned 403. | Shared navigation, dashboard links, sidebar links, and landing pages were made role-aware and routed to working pages. | Orders, settings, dashboard, and home-page actions were re-tested in the browser. |
| Social auth | Login and signup pages showed Google/Facebook buttons even when keys were placeholders, causing provider errors. | Social buttons now render only when provider credentials are actually configured. | Browser validation confirmed the broken buttons no longer appear locally. |
| Payments availability | The gateway factory exposed all registered gateways, so checkout and payment pages advertised broken Stripe actions. | Gateway availability now follows settings, Stripe enablement is computed correctly, and payment templates/views hide provider actions when unavailable. | Checkout became COD-only locally and payment pages stopped exposing broken online actions. |
| Finance subscription page | `/finances/subscription/` crashed with `Invalid filter: 'floatform'`. | The template now uses Django's `floatformat` filter correctly. | Browser validation returned HTTP 200 and rendered plan pricing again. |
| Finance add-plan flow | `/finances/plans/add/` tried to use placeholder Stripe keys locally and also wrote incompatible dj-stripe fallback records. | The local fallback now creates offline dj-stripe-compatible `Product` and `Price` rows with Stripe-shaped `stripe_data`, so subscription/payment pages work without live Stripe credentials. | Browser validation created new plans, listed them on `/finances/subscription/`, and opened their payment summaries on `/finances/payment-methods/`. |
| Content documents | Document upload failed because `Document.title` was required, redirects pointed at a nonexistent route, and hashid IDs were wired through `<int:pk>` delete URLs. | Upload now derives a title when one is omitted, redirects go to the working documents list, delete URLs use string IDs, and the active UI uses CSRF-protected POST actions. | Browser validation uploaded and deleted a real document successfully. |
| Content product flow | `/products/` was rendering a shadowed finances template with a dead `Add to Cart` button instead of the content app's purchase flow. | Content document and product views now use namespaced templates under `content/...`, which prevents cross-app template shadowing and restores the `Buy Now` handoff into payment methods. | Browser validation created a product, rendered `Buy Now`, and opened the correct product order summary on `/finances/payment-methods/`. |
| Multitenancy web flow | Tenant create/invite/detail screens depended on missing endpoints, incorrect role checks, an obsolete invitation model, and managers that ignored soft-delete state. | Tenant creation now sets a real type, invitations go through memberships, active queries respect `is_active=True`, invite/member/delete buttons post to implemented endpoints, and local side-effect delivery failures no longer break the request. | Browser validation covered tenant creation, invitation, tenant switching, member removal, and organization deletion. |
| Dashboard organizations card | The operations dashboard still listed memberships for soft-deleted organizations because it filtered only on membership state, not tenant state. | `DashboardView` now filters memberships with `tenant__is_active=True`, matching the fixed tenant pages. | Browser validation confirmed `/dashboard/` no longer shows soft-deleted workflow organizations. |
| Notifications | Notification read actions used hashid objects with `<int:pk>`, HTMX buttons without CSRF, and a bulk-read query against a nonexistent `is_read` field. | Routes now use string IDs, read actions submit through CSRF-protected POST forms, and bulk-read updates `read_at` correctly. | Browser validation marked one notification read, then marked all remaining notifications as read successfully. |
| Security settings | “Sign out all other sessions” was a dead button. | A real POST endpoint was added to revoke other Django sessions for the current user. | Browser test revoked a second active customer session and reduced the session table back to one entry. |
| Settings page | “Delete Account” was a dead destructive control. | The settings UI now marks account deletion as unavailable in the local demo instead of rendering a bogus button. | Settings page reloaded cleanly and the screenshot/manual were updated. |

## Follow-up areas not expanded in this pass

- Full provider-backed payment execution still requires valid external Stripe or Khalti credentials.
- Some optional integrations and background workers were not exercised end-to-end.
